Dynamic Programming Matrix

Examine the (m + 1) × (n + 1) matrix generated by the C program. Each cell dp[i][j] holds the LCS length of prefixes seq1[0..i-1] and seq2[0..j-1].

0: Base Case (Empty Prefix ε) dp[m][n]: Final LCS Length

Recurrence Definition:

  • If i = 0 or j = 0: dp[i][j] = 0
  • If seq1[i - 1] == seq2[j - 1]: dp[i][j] = 1 + dp[i - 1][j - 1] (Diagonal + 1)
  • Otherwise: dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]) (Max of Upper & Left)

Algorithm Explanation (Step by Step)

A structured walkthrough of the Longest Common Subsequence Dynamic Programming algorithm, designed for Analysis of Algorithms (AOA) viva preparation.

  1. 1

    Accept Two DNA Sequences

    Receive Sequence 1 of length m and Sequence 2 of length n from user input or terminal arguments.

  2. 2

    Validate the Input

    Normalize all characters to uppercase and verify that all characters belong to the DNA alphabet {A, T, G, C}. Reject invalid characters.

  3. 3

    Calculate Sequence Lengths

    Compute lengths m = strlen(seq1) and n = strlen(seq2), verifying that neither exceeds the maximum buffer size (500).

  4. 4

    Create a DP Table of Size (m + 1) × (n + 1)

    Allocate a 2D integer table where rows index characters of Sequence 1 and columns index characters of Sequence 2.

  5. 5

    Initialize First Row and First Column to Zero

    Set dp[i][0] = 0 for all i and dp[0][j] = 0 for all j, representing comparisons with an empty sequence prefix (ε).

  6. 6

    Traverse the Table Using Two Nested Loops

    Iterate row by row from i = 1 to m and column by column from j = 1 to n.

  7. 7

    Compare Current Characters

    Examine if nucleotide seq1[i - 1] is identical to nucleotide seq2[j - 1].

  8. 8

    If Characters Match, Add One to Diagonal Value

    Execute dp[i][j] = 1 + dp[i - 1][j - 1], extending the optimal subsequence found up to the preceding positions.

  9. 9

    Otherwise, Take the Larger of Upper and Left Values

    When characters differ, take max(dp[i - 1][j], dp[i][j - 1]) using an ordinary if-else statement to preserve the best previous match.

  10. 10

    Continue Until Entire Table is Filled

    Process all (m × n) subproblems bottom-up, ensuring every cell holds the optimal substructure solution.

  11. 11

    Read LCS Length from dp[m][n]

    The bottom-right cell dp[m][n] holds the exact length of the Longest Common Subsequence.

  12. 12

    Backtrack from the Bottom-Right Cell

    Initialize pointers i = m and j = n to trace the decisions that led to the optimal score.

  13. 13

    Record Matching Characters

    Whenever seq1[i - 1] == seq2[j - 1], add the character to the output buffer and decrement both i and j.

  14. 14

    Move Toward Neighboring Cell with Larger Value

    When characters differ, move to i - 1 if dp[i - 1][j] ≥ dp[i][j - 1], otherwise move to j - 1.

  15. 15

    Reverse Reconstructed Sequence

    Since backtracking collects characters from right to left, reverse the collected string to restore original 5' to 3' order.

  16. 16

    Calculate Overlap Score

    Compute (LCS Length / max(m, n)) × 100, handling zero denominator safely if both inputs are empty.

  17. 17

    Display the Final Result

    Return the reconstructed LCS string, length, overlap score, highlighted alignment, and DP matrix to the user.

Complexity Analysis

Theoretical asymptotic bounds for the Longest Common Subsequence dynamic programming approach.

TIME COMPLEXITY
O(m × n)

Quadratic in Input Lengths

The Dynamic Programming table contains (m + 1) × (n + 1) cells. Computing each individual cell requires comparing two characters and taking the maximum of two previously calculated adjacent cells, which runs in O(1) constant time.

Table Construction: O(m × n)
Backtracking Reconstruction: O(m + n)
Total Running Time: O(m × n)
SPACE COMPLEXITY
O(m × n)

Matrix Memory Allocation

To reconstruct the actual Longest Common Subsequence through backtracking, the entire 2D matrix of dimensions (m + 1) × (n + 1) must be stored in memory.

2D DP Matrix Size: (m + 1) × (n + 1) integers
LCS Reconstructed Buffer: O(min(m, n))
Total Space Usage: O(m × n)

Biological Context & Limitations

Understanding the role and constraints of algorithmic sequence comparison in computational biology.

Educational Bioinformatics Demonstration

In computational genomics, sequence alignment helps computer scientists explore algorithmic patterns in genetic text. This tool demonstrates:

  • How discrete algorithms handle long polymer strings composed of 4 nucleotide bases.
  • How Dynamic Programming solves sequence similarity problems by breaking them into overlapping subproblems.
  • How backtracking through optimal score matrices recovers actual shared subsequences.

Real-World Genomic Algorithms

Professional bioinformatics pipelines use advanced alignment scoring schemes:

  • Needleman-Wunsch: Global alignment with gap penalties and substitution matrices.
  • Smith-Waterman: Local alignment optimizing island regions of biological homology.
  • BLAST: Heuristic k-mer database search for rapid genomic lookups.
Important Scientific Disclaimer

This application is an educational demonstration. An LCS-based overlap score is not equivalent to validated biological sequence identity and cannot establish genetic relatedness, disease risk, or biological function.
